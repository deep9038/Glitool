Replaced the old Planner → Coder → Reviewer pipeline with a single unified executor agent.

**Updated:** `CLI/src/agent.ts` — replaced 6 domain branches with single `EXECUTOR_DOMAINS` check. Removed dead imports (`StructuredTool`, `EscalationPayload`), dead `tools` array, `onEscalation` param, commented code.

**Updated:** `CLI/src/ui/App.tsx` — removed `onEscalation` from `chat()` call site.

**Result:** Build passes clean. Cross-domain tasks now work. 1 LLM call instead of 3 before work starts.

## 2. bashTool Schema Fix

LLM consistently passed `timeout` as string `"120000"` and `runInBackground` as `"false"`. Schema now accepts both via `z.union`, coerced inside function body with explicit type annotations. TypeScript `spawn()` overload error fixed by explicit `: number` and `: boolean` annotations.

---

## 3. readFileTool / searchCodeTool — Removed `.transform()`

Both tools had `.transform()` at the schema object level for alias handling. LangChain cannot serialize `.transform()` to JSON Schema → "Transforms cannot be represented in JSON Schema" error → coder crashed before first tool call.

Fixed by removing `.transform()` from schema and moving alias resolution into function body.

## 7. Executor Gets Conversation History

**Problem:** The executor only received the current user message — no session history. Follow-up prompts like "do the high priority upgrades" caused the agent to start blind and re-read everything.

**Fix:** `runExecutor` now takes a `history: BaseMessage[]` param. `agent.ts` passes `trimHistory(sessionMessages)` so the executor sees the full conversation. Messages are spread before the new HumanMessage: `{ messages: [...history, new HumanMessage(userMessage)] }`.

---

## 8. Clarifier — Smarter Follow-up Detection

**Problem:** "do the high priority upgrades" was treated as a fresh vague request → clarifier asked "what upgrades?" even though they were discussed in the previous turn.

**Fix:** Added action-verb + definite-article detection. If the prompt is short, starts with an action verb (`do`, `implement`, `build`, `fix`, etc.), contains "the", and there's existing session history (`sessionMessageCount > 2`), it's treated as a follow-up referring to prior context → no clarification.

---

## 9. Human-in-the-Loop — Removed Pre-Clarifier, Added `askUser` Tool

**Big architecture change.** The pre-execution clarifier LLM call was asking questions *blind* — before seeing any code. Replaced with the agent asking informed questions mid-execution, only when genuinely stuck.

**Removed:** The clarifier LLM call entirely (no more ~7s wait before the agent starts, no more speculative/wrong questions).

**Kept:** The codebase grep in `clarifier.ts` — fast, no LLM, still gives the executor a head start via `codeContext`.

**Created:**
- `CLI/src/clarificationHandler.ts` — module-level handler (same pattern as `confirmHandler.ts`). `setClarificationHandler()` / `requestClarification()`.
- `CLI/src/tools/askUserTool.ts` — `askUser` tool the executor can call to pause and ask ONE informed question. Description restricts it to "after investigating, only when multiple real candidates exist, never for design preferences."

**Wired up:**
- `askUserTool` exported from `tools/index.ts`, added to executor's tool list.
- `agent.ts` registers `onClarificationNeeded` as the clarification handler via `setClarificationHandler()`.
- `chat()` signature changed: `onClarificationNeeded?: (question: string, options?: string[]) => Promise<string>` (single question now, not array).
- `App.tsx` updated to wrap the single question into the existing `ClarificationCard` state.

**New flow:**
```
User prompt → fast grep (no LLM) → executor starts immediately
            → if genuinely stuck, calls askUser tool → user answers → continues
            → if clear, just works
```
