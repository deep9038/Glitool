# 2026-06-01 — Spec #1: Model lineup + tier-aware context + token metering

Brainstormed and applied a five-section spec covering: simplified model lineup,
tier-aware history budgets, plan-aware CLI, token-based metering, and a signup
nudge for anon users. Also applied four edge-case fixes surfaced during review.

## What was applied

### Section 1 — Model lineup
- **Server** [`server/src/routes/proxy.ts`]: replaced `MiniMax/DeepSeek/Kimi` table with a simpler `Qwen3-Coder / DeepSeek` table.
  - `anon` + `free` → `Qwen/Qwen3-Coder-480B-A35B-Instruct-FP8` ($2/$2 per 1M tokens)
  - `pro` → `deepseek-ai/DeepSeek-V4-Pro` ($2.10/$4.40 per 1M tokens, cached input $0.20/M)
  - Classifier (internal): `Qwen2.5-7B-Instruct-Turbo` (unchanged)
- Removed: MiniMax M2.7, Kimi K2.6 (previously reserved for multimodal — dropped from active table)
- Legacy CLI hints (old vendor names) fall back to the plan's quick model — no breaking changes.

### Section 2 — Tier-aware history budgets
- **New file** [`CLI/src/llm/budgets.ts`]: `HISTORY_BUDGET` and `COMPACT_AT` keyed by plan.

| Tier | History budget | Compact at | Equivalent turns |
|---|---|---|---|
| anon | 40k chars | 30k chars | ~10 |
| free | 80k chars | 60k chars | ~20 |
| pro  | 200k chars | 150k chars | ~50 |

- `trimHistory(messages, plan)` and `compactOldMessages(messages, llm, plan)` are now tier-aware.
- Old global `MAX_HISTORY_CHARS = 60_000` removed from agent.ts.

### Section 3 — Plan-aware CLI
- **Server** [`server/src/routes/proxy.ts`]: every response now sets `X-Glitool-Plan`, `X-Glitool-Resolved-Model`, `X-Glitool-Tokens-Used`, `X-Glitool-Tokens-Limit` headers.
- **CLI** [`CLI/src/auth.ts`]: added `Plan` type, `persistPlan()`, `getCurrentPlan()`.
- **CLI** [`CLI/src/llm/factory.ts`]: `makeCaptureFetch` captures all four headers per request. New export `getTokenUsageForCurrentRequest()`.
- BYOK (`OPENAI_API_KEY` set) is treated as `pro` for budget decisions.
- Cold-start lag: at most 1 call before cached plan corrects via server header.

### Section 4 — Token metering & enforcement
- **Server** [`server/src/models/index.ts`]: added `tokens_used` field to `AnonUsage` and `Usage` (additive, default 0).
- **Server** [`server/src/middleware/checkUsageLimit.ts`]: completely rewritten — checks `tokens_used` against `TOKEN_LIMITS`.

| Tier | Cap | Server cost |
|---|---|---|
| anon | 50k tokens lifetime | ~$0.10 per user |
| free | 500k tokens / month | ~$1.00 / user / month |
| pro  | 3M tokens / month hard cap | ~$9-13 / user / month |

- 429 responses include `tier`, `tokens_used`, `tokens_limit`, helpful message, and `signup_url` / `upgrade_url` where relevant.
- **Server** [`server/src/routes/proxy.ts`]:
  - Streaming branch now parses SSE bytes to extract the final `usage` chunk (Together.ai's `stream_options.include_usage: true` was already set, we just weren't reading it).
  - Non-streaming branch already had `data.usage` — now uses it.
  - `trackUsage(req, tokens)` `$inc`s both `tokens_used` (new) and `request_count` (kept for telemetry).
- Enforcement is soft: a user at 49.5k can fire one more call and end at ~60k. Industry-standard fail-open.
- Request-ID dedup still applies: one user prompt = one token-counting event, even with 10+ ReAct iterations.

### Section 5 — Auto-compaction signup nudge
- **CLI** [`CLI/src/agent.ts`]: module-scope `nudgeShownThisSession` flag. New `onNudge` callback in `chat()`. Fires once per process when `plan === 'anon'` and compaction just happened. `clearSession()` resets the flag.
- **CLI** [`CLI/src/ui/App.tsx`]: added `'nudge'` to `Message.role`. Wired callback. Renders as `<Text color="yellow" dimColor>`.
- Nudge text: `✨ Conversation getting long — /signup gives you 2× more memory and 10× more tokens.`

### Four edge-case fixes (applied after section review)

1. **trimHistory keep-one guard** [`CLI/src/agent.ts`]: always keeps at least the most recent message even if it alone exceeds the tier budget. Prevents empty history when a single user paste is bigger than the budget.

2. **NaN token guard** [`server/src/routes/proxy.ts`]: `trackUsage` now checks `Number.isFinite(tokens)` before `$inc`. If Together returns malformed `usage`, we skip the write rather than corrupt the DB.

3. **Usage-missing warning** [`server/src/routes/proxy.ts`]: `console.warn` when the 200 response has no `usage` field (streaming or non-streaming). Surfaces silent token-capture failures in logs so we notice fast.

4. **Lower compaction min-messages threshold** [`CLI/src/memory.ts`]: was `messages.length <= KEEP_RECENT + 4`, now `<= KEEP_RECENT`. Lets compaction fire on smaller conversations where one early message is huge.

## Edge cases NOT covered (remaining)

These are edge cases identified during spec review that we deliberately did not implement, with reasoning:

### Server / model layer
- **Together.ai 503 / rate limit** — error is passed through to CLI. No retry, no fallback chain. Decision: handle if logs show this happening; not a hypothetical worth pre-building.
- **Qwen3-Coder de-serverless'd** — would require a one-line constant change + redeploy. Acceptable hot-patch path.

### Plan detection
- **`/logout` command** — not yet implemented. User has to manually delete `~/.glitool/auth.json` to log out. Pre-existing gap, out of scope here.
- **Stale `pro` plan after token revocation** — cached `auth.json` could say `pro` after admin revokes the token. CLI gets 401 on next call, but never refreshes the cached plan. No real harm — they can't make calls anyway.
- **Two CLI processes writing `auth.json` simultaneously** — last-write-wins, both writing the same plan in normal usage. Zero impact except in the very narrow downgrade-while-running scenario.

### Token metering
- **Stream interrupted mid-response (Ctrl+C)** — best-effort charging based on what arrived before disconnect. Usually correct since Together emits usage near the end.
- **Mongo write fails during trackUsage** — one free call per Mongo blip. Logged but not retried. Acceptable rarity.
- **Server restart mid-request** — dedup map in memory; restart clears it. A retry of the same request_id after restart could double-charge. Window is seconds.
- **CLI doesn't render 429 token_limit_exceeded prettily** — we send the friendly message + URL in the JSON, but the CLI error path may show it as a raw `Error: 429` until we add a specific handler. **Needs smoke test.**

### Compaction / nudge
- **Single oversized paste in fresh session** — Fix 1 above handles the immediate UX (overshoot the budget, send anyway). Fix 4 also lowers the compaction threshold. Working as intended now.
