## 2. Clarification Feature — Full Rework

### Problem identified
Original clarifier asked generic questions ("What button? What context? What error?") with no codebase knowledge. It also hallucinated file names (`LoginForm.tsx`, `ProductCard.tsx`) that don't exist in the project.

### Fix 1 — Replaced `readFileTool` scan with `searchCodeTool` grep
**File:** `CLI/src/clarifier.ts`

`quickScan` → `codebaseSearch`. Now searches the actual codebase using grep instead of guessing filenames from the prompt. Results grouped by file with line numbers.

### Fix 2 — UI keyword map
**File:** `CLI/src/clarifier.ts`

Added `UI_SEARCH_MAP` — maps plain words to searchable code patterns:
- "button" → `onClick`
- "form" → `onSubmit`
- "delete" → `delete`
- etc.

Vague prompts like "the button is not working" now trigger a targeted grep.

### Fix 3 — HTML/TSX filtering for UI queries
**File:** `CLI/src/clarifier.ts`

When prompt contains UI keywords (button, form, input, modal), `.ts` backend files are excluded from search results. Only `.html`, `.tsx`, `.jsx` results are passed to the LLM — prevents asking about backend service functions when user means a UI element.

### Fix 4 — Anti-hallucination prompt rules
**File:** `CLI/src/clarifier.ts`

System prompt updated with strict rules:
- ONLY reference files from search results — never invent
- UI elements: ignore .ts files, prioritize HTML/TSX
- If ONE HTML/TSX candidate found → return empty questions
- Max 3 questions

### Fix 5 — Skip domains
**File:** `CLI/src/clarifier.ts`

```typescript
const SKIP_DOMAINS = new Set(['chat', 'explanation']);
```

`explanation` domain added — "read this file", "explain this function" never need clarification.

### Fix 6 — Specific file/function early return
**File:** `CLI/src/clarifier.ts`

If prompt mentions a specific filename or CamelCase identifier, skip clarification in code (not relying on LLM to decide):
```typescript
const mentionsSpecific = /\b[\w/.-]+\.(tsx?|jsx?|css|html|json|md)\b/gi.test(prompt) || ...
if (mentionsSpecific) return { questions: [], codeContext };
```

### Fix 7 — Anaphora detection for follow-up questions
**File:** `CLI/src/clarifier.ts`

Short follow-up prompts with pronouns skip clarification — agent has session history:
```typescript
const hasAnaphora = /\b(that|it|this|the issue|the bug|the problem|the fix)\b/i.test(prompt);
const isShortFollowUp = prompt.trim().split(/\s+/).length < 10 && hasAnaphora;
if (isShortFollowUp) return { questions: [], codeContext: undefined };
```

### Fix 8 — Expose codeContext to agent
**Files:** `CLI/src/clarifier.ts`, `CLI/src/agent.ts`

`ClarifierResult` now returns `codeContext`. Even when no questions are asked, the codebase search results are passed to the agent as a head start:
```typescript
} else if (codeContext) {
    finalInput = `${cleanedInput}\n\n[Codebase search context]:\n${codeContext}`;
}
```

### Fix 9 — Monitor shows clarifier immediately
**File:** `CLI/src/agent.ts`

`emit('clarifier', { questions, status: 'asking' })` fires BEFORE awaiting the user's answer. Monitor now shows the clarifier event in real time.

## 5. Monitor — Full Trace Debugging

### New event types added
**File:** `monitor/public/index.html`

| Event | What it shows |
|---|---|
| `system_prompt` | The full system prompt sent to each agent |
| `enhanced_prompt` | The final input after clarifier context added |
| `tool_response` | What each tool call returned |
| `llm_message` | The LLM's reply at each ReAct step |
| `memory` | Session history count, summary status, project memory, last 4 messages |

- **`CLI/src/agent.ts`** — `on_tool_end` → `tool_response`, `on_chat_model_end` content → `llm_message`, `system_prompt` before loop, `enhanced_prompt` after clarifier, `memory` before agent runs
